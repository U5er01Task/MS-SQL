# Лекция: Манипулирование данными в MS SQL Server (DML в T-SQL)

**Курс:** Разработка баз данных в Microsoft SQL Server  
**Тема:** Язык манипулирования данными (Data Manipulation Language — DML)

---

## Введение: Место DML в экосистеме SQL

Язык SQL (Structured Query Language) делится на несколько функциональных подмножеств:

- **DDL (Data Definition Language):** Создание и изменение структуры объектов (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`).
- **DCL (Data Control Language):** Управление правами доступа (`GRANT`, `REVOKE`, `DENY`).
- **TCL (Transaction Control Language):** Управление границами транзакций (`BEGIN TRAN`, `COMMIT`, `ROLLBACK`).
- **DML (Data Manipulation Language):** Непосредственная работа со строками данных внутри существующих таблиц и представлений.

Основу DML составляют четыре классические операции (соответствующие модели CRUD в разработке ПО):

1. **`SELECT`** — Чтение и проекция данных (_Read_).
2. **`INSERT`** — Добавление новых записей (_Create_).
3. **`UPDATE`** — Модификация существующих записей (_Update_).
4. **`DELETE`** — Удаление записей (_Delete_).
5. **`MERGE`** — Атомарная синхронизация двух наборов данных (Upsert-операция).

## 1. Логический порядок обработки запроса SELECT

В отличие от большинства языков программирования (JavaScript, C#, Python), где код выполняется строго сверху вниз, инструкция `SELECT` в SQL Server выполняется оптимизатором в строго определенном логическом порядке.

Понимание этой последовательности избавляет от 90% типичных синтаксических ошибок (например, попытки использовать псевдоним столбца из `SELECT` внутри блока `WHERE`).

```
+-------------------------------------------------------+
|  Порядок написания              Порядок выполнения    |
|-------------------------------------------------------|
|  1. SELECT                      1. FROM               |
|  2. FROM                        2. ON (для JOIN)      |
|  3. WHERE                       3. JOIN               |
|  4. GROUP BY                    4. WHERE              |
|  5. HAVING                      5. GROUP BY           |
|  6. ORDER BY                    6. HAVING             |
|  7. OFFSET / FETCH              7. SELECT             |
|                                 8. DISTINCT           |
|                                 9. ORDER BY           |
|                                 10. TOP / OFFSET-FETCH|
+-------------------------------------------------------+
```

### Разбор этапов выполнения:

1. **`FROM`:** Определяются исходные таблицы, формируется декартово произведение, если таблиц несколько.
2. **`ON`:** Применяются условия сопоставления строк для операторов `JOIN`.
3. **`JOIN`:** Добавляются строки в результирующий набор в зависимости от типа соединения (`INNER`, `LEFT`, `RIGHT`, `FULL`).
4. **`WHERE`:** Построчная фильтрация. Оставляются только те строки, для которых предикат равен `TRUE`. На этом этапе нельзя использовать агрегатные функции (`COUNT`, `SUM`), так как группировка еще не произошла.
5. **`GROUP BY`:** Строки объединяются в группы по указанным колонкам.
6. **`HAVING`:** Фильтрация уже сформированных групп. Здесь работают предикаты с агрегатными функциями.
7. **`SELECT`:** Вычисляются выражения, присваиваются алиасы, формируется проекция колонок.
8. **`DISTINCT`:** Удаляются дубликаты строк из финального набора.
9. **`ORDER BY`:** Сортировка результирующего набора. Только на этом этапе становятся доступны псевдонимы (алиасы), объявленные в `SELECT`.
10. **`TOP` / `OFFSET-FETCH`:** Ограничение количества возвращаемых клиенту строк.

## 2. Учебная схема данных для примеров

Для демонстрации всех запросов лекции создадим и наполним тестовую схему интернет-магазина.

```sql
-- Создание рабочей базы данных
IF NOT EXISTS (SELECT 1 FROM sys.databases WHERE name = 'DmlDemoDb')
BEGIN
    CREATE DATABASE DmlDemoDb;
END;
GO

USE DmlDemoDb;
GO

-- Очистка старых таблиц при повторном запуске
DROP TABLE IF EXISTS dbo.OrderItems;
DROP TABLE IF EXISTS dbo.Orders;
DROP TABLE IF EXISTS dbo.Products;
DROP TABLE IF EXISTS dbo.Categories;
DROP TABLE IF EXISTS dbo.Customers;
GO

-- Таблица клиентов
CREATE TABLE dbo.Customers (
    CustomerId INT IDENTITY(1,1) CONSTRAINT PK_Customers PRIMARY KEY CLUSTERED,
    FirstName NVARCHAR(50) NOT NULL,
    LastName NVARCHAR(50) NOT NULL,
    Email VARCHAR(100) NOT NULL CONSTRAINT UQ_Customers_Email UNIQUE,
    City NVARCHAR(50) NOT NULL,
    BonusBalance DECIMAL(10,2) NOT NULL CONSTRAINT DF_Customers_BonusBalance DEFAULT 0.00,
    CreatedAt DATETIME2(0) NOT NULL CONSTRAINT DF_Customers_CreatedAt DEFAULT SYSDATETIME()
);

-- Таблица категорий
CREATE TABLE dbo.Categories (
    CategoryId INT IDENTITY(1,1) CONSTRAINT PK_Categories PRIMARY KEY CLUSTERED,
    CategoryName NVARCHAR(50) NOT NULL
);

-- Таблица товаров
CREATE TABLE dbo.Products (
    ProductId INT IDENTITY(1,1) CONSTRAINT PK_Products PRIMARY KEY CLUSTERED,
    CategoryId INT NOT NULL CONSTRAINT FK_Products_Categories REFERENCES dbo.Categories(CategoryId),
    ProductName NVARCHAR(100) NOT NULL,
    Price DECIMAL(10,2) NOT NULL CONSTRAINT CK_Products_Price CHECK (Price >= 0),
    StockQuantity INT NOT NULL CONSTRAINT CK_Products_Stock CHECK (StockQuantity >= 0),
    IsDiscontinued BIT NOT NULL CONSTRAINT DF_Products_IsDiscontinued DEFAULT 0
);

-- Таблица заказов
CREATE TABLE dbo.Orders (
    OrderId INT IDENTITY(1001,1) CONSTRAINT PK_Orders PRIMARY KEY CLUSTERED,
    CustomerId INT NOT NULL CONSTRAINT FK_Orders_Customers REFERENCES dbo.Customers(CustomerId),
    OrderDate DATETIME2(0) NOT NULL CONSTRAINT DF_Orders_OrderDate DEFAULT SYSDATETIME(),
    TotalAmount DECIMAL(12,2) NOT NULL CONSTRAINT DF_Orders_TotalAmount DEFAULT 0.00,
    Status VARCHAR(20) NOT NULL CONSTRAINT CK_Orders_Status CHECK (Status IN ('Pending', 'Paid', 'Shipped', 'Cancelled'))
);

-- Таблица позиций заказа
CREATE TABLE dbo.OrderItems (
    OrderItemId INT IDENTITY(1,1) CONSTRAINT PK_OrderItems PRIMARY KEY CLUSTERED,
    OrderId INT NOT NULL CONSTRAINT FK_OrderItems_Orders REFERENCES dbo.Orders(OrderId) ON DELETE CASCADE,
    ProductId INT NOT NULL CONSTRAINT FK_OrderItems_Products REFERENCES dbo.Products(ProductId),
    Quantity INT NOT NULL CONSTRAINT CK_OrderItems_Quantity CHECK (Quantity > 0),
    UnitPrice DECIMAL(10,2) NOT NULL
);
GO
```

## 3. Оператор INSERT: Добавление данных

Команда `INSERT` добавляет одну или несколько строк в таблицу.

### 3.1. Базовый синтаксис и правила хорошего тона

**Плохая практика:** вставка без перечисления колонок (при изменении порядка или добавлении новых колонок в схему продакшн-код сломается).

```sql
-- Антипаттерн:
-- INSERT INTO dbo.Categories VALUES ('Электроника');
```

**Рекомендуемый стандарт:** явный список целевых колонок:

```sql
INSERT INTO dbo.Categories (CategoryName)
VALUES (N'Компьютеры и ноутбуки');
```

### 3.2. Многострочная вставка (Multi-row VALUES)

Начиная с SQL Server 2008 поддерживается вставка множества строк в рамках одной инструкции (до 1000 строк за один раз):

```sql
INSERT INTO dbo.Categories (CategoryName)
VALUES
    (N'Смартфоны и гаджеты'),
    (N'Периферия и аксессуары'),
    (N'Бытовая техника');

INSERT INTO dbo.Products (CategoryId, ProductName, Price, StockQuantity, IsDiscontinued)
VALUES
    (1, N'Ноутбук ThinkBook 16', 85000.00, 12, 0),
    (1, N'Ультрабук XPS 13', 145000.00, 5, 0),
    (2, N'Смартфон Pixel 8', 69990.00, 20, 0),
    (2, N'Смартфон Galaxy S24', 79990.00, 15, 0),
    (3, N'Механическая клавиатура', 8500.00, 45, 0),
    (3, N'Беспроводная мышь', 3200.00, 60, 0),
    (1, N'Устаревший нетбук', 12000.00, 0, 1);
```

### 3.3. Вставка результата запроса: INSERT INTO ... SELECT

Используется при миграциях, архивации или переносе данных между сущностями:

```sql
-- Создадим таблицу для VIP-клиентов
CREATE TABLE dbo.VipCustomers (
    VipId INT IDENTITY(1,1) PRIMARY KEY,
    CustomerId INT NOT NULL,
    CustomerEmail VARCHAR(100) NOT NULL,
    RegistrationYear INT NOT NULL
);

-- Наполним клиентов
INSERT INTO dbo.Customers (FirstName, LastName, Email, City, BonusBalance, CreatedAt)
VALUES
    (N'Алексей', N'Иванов', 'alex.ivanov@mail.ru', N'Москва', 1500.00, '2023-01-15 10:00:00'),
    (N'Мария', N'Петрова', 'maria.p@yandex.ru', N'Тула', 350.00, '2023-04-12 14:30:00'),
    (N'Дмитрий', N'Сидоров', 'dmitry.s@gmail.com', N'Москва', 4200.00, '2022-11-05 09:15:00'),
    (N'Елена', N'Кузнецова', 'elena.k@rambler.ru', N'Санкт-Петербург', 0.00, '2024-02-01 11:45:00');

-- Копируем клиентов с балансом бонусов > 1000 рублей в VIP
INSERT INTO dbo.VipCustomers (CustomerId, CustomerEmail, RegistrationYear)
SELECT
    c.CustomerId,
    c.Email,
    YEAR(c.CreatedAt)
FROM dbo.Customers AS c
WHERE c.BonusBalance > 1000.00;
```

### 3.4. Создание таблицы «на лету»: SELECT ... INTO

Инструкция создает новую постоянную или временную таблицу на основе схемы и типов результирующего набора данных:

```sql
-- Создание резервной архивной таблицы на лету
SELECT
    ProductId,
    ProductName,
    Price,
    StockQuantity
INTO dbo.Products_Backup_2026
FROM dbo.Products
WHERE IsDiscontinued = 0;
```

> **Внимание:** `SELECT INTO` переносит структуру столбцов и признак `NULL/NOT NULL`, но **не переносит** внешние ключи (`FK`), первичные ключи (`PK`), триггеры и индексы.

### 3.5. Работа со столбцами IDENTITY

Если требуется принудительно вставить конкретное числовое значение в столбец со свойством автоинкремента (`IDENTITY`), необходимо явно включить режим `IDENTITY_INSERT`:

```sql
SET IDENTITY_INSERT dbo.Customers ON;

INSERT INTO dbo.Customers (CustomerId, FirstName, LastName, Email, City, BonusBalance, CreatedAt)
VALUES (999, N'Сервисный', N'Аккаунт', 'system@shop.local', N'Новомосковск', 0, SYSDATETIME());

SET IDENTITY_INSERT dbo.Customers OFF;
```

## 4. Оператор SELECT: Выборка, фильтрация и сортировка

### 4.1. Базовая фильтрация с помощью WHERE

Предикаты в блоке `WHERE` вычисляются по правилам трехзначной логики (Three-Valued Logic: `TRUE`, `FALSE`, `UNKNOWN`).

```sql
-- Поиск товаров в ценовом диапазоне с проверкой активности
SELECT
    p.ProductId,
    p.ProductName,
    p.Price,
    p.StockQuantity
FROM dbo.Products AS p
WHERE p.Price BETWEEN 5000.00 AND 80000.00
  AND p.StockQuantity > 0
  AND p.IsDiscontinued = 0;
```

### 4.2. Работа со списками (IN) и шаблонами поиска (LIKE)

- `%` — любая последовательность из 0 или более символов.
- `_` — ровно один любой символ.
- `[A-Z]` — один символ из диапазона.
- `[^A-Z]` — один символ, не входящий в диапазон.

```sql
-- Клиенты из Москвы или Тулы с почтовым ящиком на доменах mail.ru или yandex.ru
SELECT
    c.CustomerId,
    c.LastName + ' ' + c.FirstName AS FullName,
    c.Email,
    c.City
FROM dbo.Customers AS c
WHERE c.City IN (N'Москва', N'Тула')
  AND (c.Email LIKE '%@mail.ru' OR c.Email LIKE '%@yandex.ru');
```

### 4.3. Опасности трехзначной логики и значения NULL

`NULL` означает отсутствие значения или неизвестность. Сравнение `NULL = NULL` вернет `UNKNOWN`, а не `TRUE`.

```sql
-- Неверно: ничего не вернет
-- SELECT * FROM dbo.Customers WHERE City = NULL;

-- Корректно:
SELECT CustomerId, FirstName, Email
FROM dbo.Customers
WHERE City IS NOT NULL;
```

Функции для безопасной обработки неопределенных значений:

- `ISNULL(check_expression, replacement_value)` — встроенная быстрая функция T-SQL.
- `COALESCE(val1, val2, ..., valN)` — стандарт ANSI SQL, возвращает первый аргумент, отличный от `NULL`.

## 5. Объединение таблиц (JOIN)

В реляционных базах данные нормализованы и разнесены по разным таблицам. Для сборки единой картины используются соединения.

Добавим тестовые заказы для демонстрации:

```sql
INSERT INTO dbo.Orders (CustomerId, TotalAmount, Status, OrderDate)
VALUES
    (1, 93500.00, 'Paid', '2026-03-01 12:00:00'),
    (1, 145000.00, 'Shipped', '2026-03-05 15:30:00'),
    (2, 69990.00, 'Pending', '2026-03-08 18:20:00');
    -- Заметьте: у клиентов 3, 4 и 999 заказов пока нет!
```

### 5.1. INNER JOIN (Внутреннее соединение)

Возвращает только те строки, для которых нашлось совпадение по условию `ON` в обеих таблицах:

```sql
SELECT
    o.OrderId,
    o.OrderDate,
    c.LastName + ' ' + c.FirstName AS CustomerName,
    c.Email,
    o.TotalAmount,
    o.Status
FROM dbo.Orders AS o
INNER JOIN dbo.Customers AS c
    ON o.CustomerId = c.CustomerId;
```

### 5.2. LEFT (OUTER) JOIN (Левое внешнее соединение)

Возвращает абсолютно **все** строки из левой таблицы. Если в правой таблице совпадения нет, поля правой таблицы заполняются значениями `NULL`.

```sql
-- Показываем ВСЕХ клиентов и суммы их заказов (если они были)
SELECT
    c.CustomerId,
    c.LastName + ' ' + c.FirstName AS CustomerName,
    o.OrderId,
    o.TotalAmount,
    ISNULL(o.Status, 'No Orders') AS OrderStatus
FROM dbo.Customers AS c
LEFT JOIN dbo.Orders AS o
    ON c.CustomerId = o.CustomerId
ORDER BY c.CustomerId;
```

### 5.3. Поиск записей-сирот (Anti-Semi Join паттерн)

Найти клиентов, которые зарегистрировались, но ни разу не сделали ни одного заказа:

```sql
SELECT
    c.CustomerId,
    c.FirstName,
    c.LastName,
    c.Email
FROM dbo.Customers AS c
LEFT JOIN dbo.Orders AS o
    ON c.CustomerId = o.CustomerId
WHERE o.OrderId IS NULL;
```

### 5.4. CROSS JOIN (Декартово произведение)

Каждая строка первой таблицы соединяется с каждой строкой второй таблицы. Если в таблице А 10 строк, а в таблице Б 100 строк — результат вернет 1000 строк. Полезен для генерации сетки дат, матриц и комбинаторных тестов:

```sql
-- Получить все возможные комбинации категорий и городов
SELECT
    cat.CategoryName,
    cities.City
FROM dbo.Categories AS cat
CROSS JOIN (
    SELECT DISTINCT City FROM dbo.Customers
) AS cities;
```

## 6. Агрегация данных: GROUP BY и фильтрация HAVING

Агрегатные функции (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`) сворачивают множество строк в одно итоговое значение.

### 6.1. Правило золотого стандарта GROUP BY

> **Критическое правило:** Если в запросе присутствует предложение `GROUP BY`, то **любой** столбец, указанный в блоке `SELECT`, обязан либо входить в список группировки `GROUP BY`, либо быть обернут в агрегатную функцию.

```sql
-- Подсчет количества товаров, средней и минимальной цены по каждой категории
SELECT
    cat.CategoryName,
    COUNT(p.ProductId) AS ProductsCount,
    AVG(p.Price) AS AveragePrice,
    MIN(p.Price) AS MinPrice,
    MAX(p.Price) AS MaxPrice
FROM dbo.Categories AS cat
INNER JOIN dbo.Products AS p
    ON cat.CategoryId = p.CategoryId
GROUP BY cat.CategoryName;
```

### 6.2. Разница между WHERE и HAVING

- `WHERE` фильтрует исходные строки **до** того, как они будут сгруппированы.
- `HAVING` фильтрует агрегированные группы **после** их формирования.

```sql
-- Категории, в которых средняя цена активных товаров превышает 10 000 руб
SELECT
    cat.CategoryName,
    COUNT(p.ProductId) AS TotalItems,
    AVG(p.Price) AS AvgPrice
FROM dbo.Categories AS cat
INNER JOIN dbo.Products AS p
    ON cat.CategoryId = p.CategoryId
WHERE p.IsDiscontinued = 0     -- Фильтрация строк до группировки
GROUP BY cat.CategoryName
HAVING AVG(p.Price) > 10000.00 -- Фильтрация групп после вычисления среднего
ORDER BY AvgPrice DESC;
```

## 7. Оператор UPDATE: Изменение существующих данных

Инструкция `UPDATE` изменяет значения в одном или нескольких столбцах существующих строк таблицы.

### 7.1. Базовый синтаксис

> **Предостережение:** Выполнение команды `UPDATE` без предложения `WHERE` изменит данные во **всех** строках таблицы без исключения.

```sql
-- Начисление приветственных 500 бонусов всем клиентам из Тулы
UPDATE dbo.Customers
SET BonusBalance = BonusBalance + 500.00
WHERE City = N'Тула';
```

### 7.2. UPDATE с использованием JOIN

В реальных базах условие обновления одной таблицы часто зависит от данных в другой связанной таблице. В T-SQL доступна проприетарная и очень удобная конструкция обновления через `JOIN`:

```sql
-- Пересчитать общую сумму в таблице Orders на основе реальных строк OrderItems
-- Добавим тестовую позицию в заказ 1001
INSERT INTO dbo.OrderItems (OrderId, ProductId, Quantity, UnitPrice)
VALUES (1001, 1, 1, 85000.00), (1001, 5, 1, 8500.00);

-- Обновление суммы заказа по фактической стоимости позиций
UPDATE o
SET o.TotalAmount = items.CalculatedTotal
FROM dbo.Orders AS o
INNER JOIN (
    SELECT
        OrderId,
        SUM(Quantity * UnitPrice) AS CalculatedTotal
    FROM dbo.OrderItems
    GROUP BY OrderId
) AS items ON o.OrderId = items.OrderId
WHERE o.Status = 'Pending';
```

## 8. Операторы DELETE и TRUNCATE: Удаление данных

Удаление информации — необратимая операция на уровне бизнес-логики (если не настроены бэкапы или мягкое удаление Soft Delete).

### 8.1. Оператор DELETE

- Построчно удаляет записи, удовлетворяющие условию `WHERE`.
- Каждая удаляемая строка подробно логируется в Transaction Log (`.ldf`).
- Активирует триггеры удаления (`ON DELETE`).
- Не сбрасывает счетчик `IDENTITY`.
- Поддерживает соединение через `JOIN`.

```sql
-- Удаление клиентов, у которых нет заказов и нулевой бонусный баланс
DELETE c
FROM dbo.Customers AS c
LEFT JOIN dbo.Orders AS o ON c.CustomerId = o.CustomerId
WHERE o.OrderId IS NULL
  AND c.BonusBalance = 0;
```

### 8.2. Команда TRUNCATE TABLE (DDL с поведением очистки)

`TRUNCATE TABLE` — это команда DDL, которая мгновенно очищает всю таблицу целиком.

```sql
TRUNCATE TABLE dbo.Products_Backup_2026;
```

### Сравнительная таблица DELETE vs TRUNCATE

| Характеристика                 | DELETE                                | TRUNCATE TABLE                            |
| :----------------------------- | :------------------------------------ | :---------------------------------------- |
| **Категория команды**          | DML (Data Manipulation)               | DDL (Data Definition)                     |
| **Условие WHERE**              | Поддерживается (удаление части строк) | Не поддерживается (удаляет строго всё)    |
| **Журналирование**             | Построчное (тяжелая нагрузка на диск) | Минимальное (освобождение страниц)        |
| **Сброс IDENTITY**             | Счетчик сохраняет последнее значение  | Сбрасывает счетчик к исходному Seed       |
| **Срабатывание DML-триггеров** | Срабатывают триггеры `FOR DELETE`     | Триггеры игнорируются                     |
| **Внешние ключи (FK)**         | Работает при соблюдении связей        | Блокируется, если на таблицу ссылается FK |
| **Скорость выполнения**        | Медленно на миллионах строк           | Мгновенно (миллисекунды)                  |

## 9. Оператор MERGE: Синхронизация данных (Upsert)

Оператор `MERGE` выполняет вставку, обновление или удаление данных в целевой таблице (`Target`) на основе сопоставления с таблицей-источником (`Source`) в рамках единой неделимой инструкции.

Классический сценарий: обновление каталога товаров из выгрузки 1C, CRM или внешнего поставщика:

- Если товар уже существует — обновить его цену и остаток.
- Если товара еще нет в каталоге — добавить новую запись.

```sql
-- Таблица входящих изменений от поставщика
DECLARE @SupplierFeed TABLE (
    ProductName NVARCHAR(100),
    CategoryName NVARCHAR(50),
    Price DECIMAL(10,2),
    StockQuantity INT
);

INSERT INTO @SupplierFeed (ProductName, CategoryName, Price, StockQuantity)
VALUES
    (N'Смартфон Pixel 8', N'Смартфоны и гаджеты', 64990.00, 35), -- Товар есть: обновится цена и остаток
    (N'Планшет Pro 11', N'Смартфоны и гаджеты', 54000.00, 8);      -- Товара нет: добавится новая запись

-- Синхронизация каталога Products с входящим фидом
MERGE dbo.Products AS Target
USING (
    SELECT
        feed.ProductName,
        cat.CategoryId,
        feed.Price,
        feed.StockQuantity
    FROM @SupplierFeed AS feed
    INNER JOIN dbo.Categories AS cat ON feed.CategoryName = cat.CategoryName
) AS Source
ON (Target.ProductName = Source.ProductName)

-- 1. СОВПАДЕНИЕ: обновляем существующий товар
WHEN MATCHED THEN
    UPDATE SET
        Target.Price = Source.Price,
        Target.StockQuantity = Source.StockQuantity,
        Target.IsDiscontinued = 0

-- 2. НЕТ В ЦЕЛЕВОЙ ТАБЛИЦЕ: вставляем новый товар
WHEN NOT MATCHED BY TARGET THEN
    INSERT (CategoryId, ProductName, Price, StockQuantity, IsDiscontinued)
    VALUES (Source.CategoryId, Source.ProductName, Source.Price, Source.StockQuantity, 0);
-- ОБЯЗАТЕЛЬНО: инструкция MERGE должна заканчиваться точкой с запятой!
```

## 10. Продвинутые возможности: Секция OUTPUT

Секция `OUTPUT` возвращает информацию о строках, затронутых операциями `INSERT`, `UPDATE`, `DELETE` или `MERGE`. Она предоставляет доступ к виртуальным псевдотаблицам:

- **`inserted`:** содержит новые или обновленные значения строк.
- **`deleted`:** содержит старые значения строк до обновления или удаленные записи.

### 10.1. Аудит изменений при UPDATE

```sql
-- Создадим таблицу истории изменения цен
CREATE TABLE dbo.PriceHistory (
    HistoryId INT IDENTITY(1,1) PRIMARY KEY,
    ProductId INT NOT NULL,
    OldPrice DECIMAL(10,2) NOT NULL,
    NewPrice DECIMAL(10,2) NOT NULL,
    ChangeDate DATETIME2(0) NOT NULL
);

-- Повышаем цены на 10% и одновременно логируем изменения в аудит-таблицу
UPDATE dbo.Products
SET Price = Price * 1.10
OUTPUT
    inserted.ProductId,
    deleted.Price AS OldPrice,
    inserted.Price AS NewPrice,
    SYSDATETIME()
INTO dbo.PriceHistory (ProductId, OldPrice, NewPrice, ChangeDate)
WHERE CategoryId = 1;
```

### 10.2. Получение ID только что вставленных строк

В веб-разработке после создания заказа часто требуется сразу вернуть его первичный ключ на бэкенд:

```sql
INSERT INTO dbo.Orders (CustomerId, TotalAmount, Status)
OUTPUT inserted.OrderId, inserted.OrderDate
VALUES (2, 4500.00, 'Pending');
```

## 11. Управление транзакциями (TCL) и защита данных

По умолчанию SQL Server работает в режиме автоматической фиксации (**Auto-commit**): каждая одиночная инструкция DML считается отдельной транзакцией и сразу фиксируется на диске.

Если бизнес-операция состоит из нескольких связанных шагов (например, списание денег со счета клиента и создание записи о заказе), их необходимо объединять в явную транзакцию.

### Шаблон безопасного выполнения DML с обработкой ошибок

```sql
BEGIN TRANSACTION;

BEGIN TRY
    -- Шаг 1: Уменьшаем остаток товара на складе
    UPDATE dbo.Products
    SET StockQuantity = StockQuantity - 1
    WHERE ProductId = 1 AND StockQuantity >= 1;

    -- Проверяем, обновилась ли строка
    IF @@ROWCOUNT = 0
    BEGIN
        RAISERROR(N'Недостаточно товара на складе для оформления заказа!', 16, 1);
    END;

    -- Шаг 2: Создаем заказ
    INSERT INTO dbo.Orders (CustomerId, TotalAmount, Status)
    VALUES (1, 85000.00, 'Paid');

    -- Шаг 3: Фиксируем транзакцию, если все шаги прошли успешно
    COMMIT TRANSACTION;
    PRINT N'Транзакция успешно зафиксирована!';
END TRY
BEGIN CATCH
    -- Если произошла ошибка (сбой сервера, нарушение CHECK-ограничения) — откатываем всё
    IF @@TRANCOUNT > 0
    BEGIN
        ROLLBACK TRANSACTION;
    END;

    -- Логируем или пробрасываем ошибку
    PRINT N'Ошибка транзакции: ' + ERROR_MESSAGE();
END CATCH;
```
